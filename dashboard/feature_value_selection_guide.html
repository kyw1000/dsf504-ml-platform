📐 General Principles

A structured 5-step process for deciding which feature values to keep, transform, or discard.

1Detect Anomalies

  • Domain impossibilities (age=0, util=50,708)
  • Sentinel / error codes (96, 98 in DPD)
  • Impossible negatives
  • Constant & near-zero variance cols

2Measure Skew

  • Skewness |s| > 1 → log/sqrt transform
  • |s| > 5 → Winsorise first, then log
  • Bimodal → split into indicator + value
  • Heavy tail vs. outlier vs. error

3Target Linkage

  • Compute default/fraud rate per bin
  • Monotonic → keep raw or binned
  • Non-monotonic → flag as interaction
  • Flat → candidate for removal

4Choose Treatment

  • Clip: known physical bounds
  • Winsorise: statistical extreme
  • Log1p: right skew, all positive
  • Indicator: missingness = signal

5Validate on Val

  • Apply train-set stats only
  • Check clip bounds don't break val
  • Verify no leakage introduced
  • Retrain baseline, compare AUC

Temporal Values — TransactionDT
⏰Extract cyclic time features from epoch secondsHigh value

Fraud rate peaks at 2–4 AM (∼8% vs ∼3% daytime). Derive:
• tx_hour = (TransactionDT // 3600) % 24 → then sin/cos encoding
• tx_day_of_week = (TransactionDT // 86400) % 7
• Keep raw TransactionDT for tree models (they split on raw values natively)

Why sin/cos: a linear model sees hour 23 and hour 0 as far apart (distance=23). With cyclic encoding the distance is 1/24.

DebtRatio — Non-monotonic at extreme values
⚠️Max=329,664 — mathematically impossible as a ratioCritical

The highest debt ratio bin (>3.66) paradoxically shows lower default (5.5%) than the second-highest bin (9.9%). This occurs because extreme DebtRatio values arise when monthly income ≈ 0 (e.g., unemployed) — the ratio is undefined/meaningless, not actually extreme debt.
• Winsorise at p99 (≈4,977) using train statistics
• Create is_debtration_extreme (DebtRatio > 1.0) — signals debt exceeds income
• Consider abs_debt = DebtRatio × MonthlyIncome as a more meaningful derived feature

TF-IDF Value Selection
📝min_df and max_df control which token values enter the vocabularyKey parameter

min_df=2 (recommended): removes hapax legomena — tokens that appear in only 1 sentence. With 2,264 sentences, a token appearing once contributes 0 information for generalisation and inflates dimensionality.
max_df=0.95: removes tokens present in 95%+ of sentences — financial boilerplate ("company", "said", "year") that appears regardless of sentiment.
sublinear_tf=True: replaces raw term frequency tf with log(1+tf) — prevents "profit profit profit" from dominating "profit grew by 30%".

🔢Vocabulary size: 5,000 features vs. 2,264 sentencesDimension choice

With only 2,264 training sentences, a 5,000-token vocabulary gives ∼2.2 samples per feature — borderline for regularised models. Recommendations by model type:
• Logistic Regression (with L2): 5,000 is fine — L2 penalises irrelevant dimensions
• LightGBM: 5,000 is fine — tree models ignore irrelevant features via splitting
• Naive Bayes: reduce to 3,000 — NB struggles more with large sparse vocabularies
• If FinBERT unavailable: increase to 8,000 to compensate for semantic loss

Rule of thumb: vocabulary_size ≤ 2–3× training samples for unregularised models (Zhang & LeCun, 2015).

Loughran-McDonald Word List Values
📚Finance-domain lexicon outperforms Harvard GI for financial textDomain-specific

Which word list values to use:
• lm_positive / lm_negative: raw counts. Note that "liability", "loss", "risk" appear in neutral filings — use ratio (lm_pos / (lm_neg + 1)) to measure directional tilt
• lm_uncertainty ("may", "could", "approximately"): useful for distinguishing neutral from positive — high uncertainty language ≈ neutral regardless of positive word count
• lm_modal_strong ("will", "shall", "must"): high confidence forward statements signal positive outlook
• Exclude: Harvard GI negative words — "liability", "cost", "tax" are classified negative by Harvard but are neutral in financial reporting context (Loughran & McDonald, 2011)

FinBERT Token Truncation
✂️All sentences fit within 512-token limit — no truncation neededConfirmed safe

Max sentence length in the dataset is under 100 tokens (words × ∼1.3 subword ratio). FinBERT's 512-token limit is never hit. However:
• Use [CLS] token embedding (position 0) — this is the classification head's representation
• Do not mean-pool all tokens — FinBERT was fine-tuned with CLS pooling for sentiment
• Batch size: 32 on GPU, reduce to 8 on CPU to avoid OOM on the 768-dim forward pass

The 6 Universal Rules of Feature Value Selection
1Never clip before measuring target rate per rangeMost common mistake

The data showed: RevolvingUtil 1–2 has 40% default rate. A "clip to [0,1]" would have destroyed the most predictive value range in the entire dataset. Always compute event rate per value band before deciding on clipping bounds.

2Compute all statistics on training data onlyLeakage

Clip bounds, Winsorisation percentiles, imputation medians, frequency-encoding maps, TF-IDF vocabulary — all must be computed on the training fold and applied to validation/test. Re-computing on the full dataset is data leakage and inflates validation performance.

3Error codes are information, not noiseCommon pitfall

DPD 96/98 rows had a 54.7% default rate. An "unknown" or "not applicable" sentinel value often marks a specific sub-population (e.g., borrowers with no credit history, commercial accounts). Create a binary flag for the sentinel, then clamp the numeric field.

4Distinguish outlier types before treatingTreatment varies

Three different outlier types require three different treatments:
• Domain violation (age=0, util=50,708): clip to physically valid range
• Measurement error (income=$3M): Winsorise at p99 train-only, add flag
• Valid extreme (transaction=$31,936): keep — may carry disproportionate signal

5Monotonic relationships → keep raw; non-monotonic → create interactionTarget linkage

Age → default rate is cleanly monotonic (10.4% → 2.5%) — keep age as numeric. NumOpenLoans is non-monotonic (highest default at <4 loans, then drops, then rises) — this signals an interaction with revolving vs. installment loan type. Create has_no_loans flag + raw count.

6Missingness pattern is a feature, not a problemSignal extraction

MonthlyIncome missing (19.8%) is not random — lower-income borrowers are more likely to leave income blank. Create is_income_missing before imputing, and verify the missing rows have a different target rate. In fraud detection, a missing device fingerprint often indicates a burner device.
